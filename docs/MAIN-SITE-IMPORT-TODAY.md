## 分類請這樣分（比字數更重要）

| 分類 | 適合什麼 | 不適合 |
|------|----------|--------|
| **隨想** | 碎念、抱怨、隨便發、短想法 | 有完整一天敘事的札記 |
| **日記** | 生活札記、當天紀錄、入學／旅行日記 | 純抱怨一兩句 |
| **隨筆** | 整理過的散文、有主題的心情文 | 未整理的碎念 |
| **心得** | 讀書／觀影／作品感想 | 原創小說 |
| **創作** | 小說、詩、劇本、短篇 | 讀後感 |
| **長文** | 長篇論述、系列長筆記 | 短碎念 |

系統會依標題／內文**謹慎推測**（例如「生活札記」→日記、「閱讀心得」→心得），不確定時請在後台點分類按鈕確認。

列表篩選：[`literature.html`](https://linyize1111.github.io/literature.html) 可「只看隨想」「只看日記」等。  
隨想與日記在列表都用較輕量的卡片。

## 三步流程

1. **貼上** — Threads／FB／備忘錄／HackMD 全文  
2. **存成草稿**  
3. **確認分類** — 頂部標題看清楚是哪篇 → 點 隨想／日記／心得／創作… → 要上架再改「發佈」

標籤預設空白；可選：抱怨、想法、生活、閱讀、摘錄。

## 想全部重來？不麻煩

**不會很麻煩。** 建議兩種：

### A. 軟重置（保留文章、先下架）

在後台把搞混的篇改成 **草稿**，一篇篇改標題／分類／摘要後再發佈。  
ID、網址 slug 可維持不變。

### B. 硬重置（清空再重貼）

1. 後台刪除要重做的篇（或請我幫你用 SQL 清 `articles`）  
2. 你把原文貼給我（或貼進後台）  
3. 我幫你：**排版（Markdown）、分類、標籤、摘要**  
4. 你在後台確認後發佈  

**不會動到：** 登入、Google OAuth、Supabase 金鑰、ACG 站。  
只動文章內容表（必要時連封面 Storage）。

本地還有 `temp-pages/literature/*.md` 可當來源；站上缺的篇以你貼的全文為準。

若要走 B，跟我說「清空文學區重來」或「只清草稿」，並把文稿一批批貼過來即可。
