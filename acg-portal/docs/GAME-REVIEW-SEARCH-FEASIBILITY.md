# 遊戲評鑑自動填入：標題／以圖搜圖可行性評估

**狀態**：評估文件（v1.5.0 之後）  
**範圍**：不依賴 RJ／VJ 代碼，改以**標題**或**封面／圖片**找出作品詳情  
**現況基準**：見 [`GAME-REVIEW-AUTOFILL.md`](./GAME-REVIEW-AUTOFILL.md)、migration `0017_game_dlsite_autofill.sql`  
**結論先行**：短期應把「標題 → 候選列表 → 站長確認」當主路徑並強化 UX；以圖搜圖可做但建議當輔助且必須人工確認；不要做全自動無確認、不要接盜版站。

## 決策紀錄（2026-07-19／v1.6.0）

| 項目 | 決策 |
|------|------|
| **P0 標題搜尋產品化** | ✅ 已做：UX 以標題為主、名稱預填、「用上方名稱搜尋」、候選店家徽章、空結果引導；RPC soft empty + `hint`；保留 RJ／URL 進階 |
| **P1 以圖搜圖** | ⏸ UI 預留＋文件（無 SauceNAO API key，不實作呼叫／不暴露 secret） |
| **P1 Steam 等** | ⏸ 未做；不拖垮 P0，列後續 |
| 分項分數 | 仍不自動填 |
| 全自動取第一筆 | 不做 |

實作：`0018_game_title_search_primary.sql`、前端編輯器面板、本決策後請以 [`GAME-REVIEW-AUTOFILL.md`](./GAME-REVIEW-AUTOFILL.md) 為使用說明。

## 0. 現有架構（與評估相關的事實）

```text
管理員前端（app.js）
  → supabase.rpc('admin_fetch_game_metadata', { query })
  → Postgres security definer（is_admin）
  → extensions.http GET DLsite
       1) product.json?workno=…     （RJ／URL：高準）
       2) fsr/=/…/keyword/… HTML    （關鍵字：候選列表）
  → { mode: detail|search, product?, candidates[] }
```

| 已有能力 | 說明 |
|----------|------|
| 標題關鍵字搜尋 | `search_dlsite_candidates` 已實作；回傳最多 8 筆（封面、社團、代碼、來源 URL） |
| 候選列表 UI | `renderGameAutofillResults`：**套用此筆**／開來源；關鍵字路徑**不會**自動套用 |
| 代碼／URL 路徑 | `mode=detail` 會**直接套用**（仍不填分數） |
| 封面上傳 | `game-covers` Storage（≤5MB）；目前只用於儲存，**未接**以圖搜圖 |
| API key | DLsite 路徑**不需**金鑰；前端僅 anon + JWT |
| Edge Function | **尚未**用於自動填入 |

**雛形準確率（經驗預期，非正式評測）**

- 日文原名／常見英文品牌名（如 `ensemble`）：常能回傳合理候選。
- 中文翻譯名、破解站改標題、過度簡短關鍵字：易空結果或錯序；文件與 UI 已標「代碼／URL 最穩」。
- 搜尋依賴 HTML `product_id/RJxxxx` regex，站點改版會整條關鍵字路徑失效（封鎖／結構風險）。

## 1. 標題搜尋

### 1.1 技術可行性：**高**（DLsite 已半成品）；跨平台總體：**中**

| 子路徑 | 可行性 | 備註 |
|--------|--------|------|
| DLsite 關鍵字 → 候選 → 確認 → 詳情 | **高** | 後端＋前端候選 UI 已存在 |
| Steam Store 搜尋 API → 候選 | **高～中** | 公開搜尋／appdetails 相對穩；適合非同人／Steam 發行作 |
| Google／Bing Custom Search（站內限定） | **中** | 需 API key＋付費額度；結果是連結，還要二次解析 |
| Fanza／Getchu 關鍵字 | **低～中** | 反爬、地區、成人 Cookie、ToS；維護成本高 |
| 多源聚合（DLsite＋Steam＋…） | **中** | 技術可行；產品與去重／排序複雜度上升 |

### 1.2 準確率預期（黃油／同人現實限制）

| 情境 | 預期 |
|------|------|
| 日文原名＋較完整標題 | 高：常落在前幾筆 |
| 官方英文名／羅馬字 | 中～高：視店家索引 |
| 繁中／簡中翻譯名 | **中～低**：DLsite 日文索引常對不上；需人工改用原名或另源 |
| 同名／系列作／重製 | **必須候選確認**；不可自動取第一筆 |
| 破解站標題（去空格、加「中文」「完結」等） | **低**；正規店家搜尋幾乎無效 |
| 中英日混用／錯字 | 低～中；模糊匹配有限 |

**產品含義**：標題搜尋的價值在「加速找對作品」，不在「免思考自動填」。準確率上限由**人工選候選**決定。

### 1.3 可用資料源（標題）

| 資料源 | 實際可用？ | CORS／反爬 | 付費 | ToS 風險 | 評估建議 |
|--------|------------|------------|------|----------|----------|
| **DLsite 關鍵字 HTML** | ✅ 已接 | 無 CORS（DB 端 http）；HTML 改版／封鎖風險 | 免費 | 非正式 API；應限 admin、低 QPS、禮貌 UA | **短期主源** |
| DLsite `product.json` | ✅ 已接 | 同上；代碼路徑穩定 | 免費 | 同上 | 詳情抓取保留 |
| **Steam** `store.steampowered.com` 搜尋／詳情 | ✅ 可行 | 伺服器端；偶有限流 | 免費（有 rate 慣例） | 相對友善；勿高頻爬 | **跨平台 P1** |
| Google Custom Search JSON API | ✅ 可行 | 無 CORS（後端） | 有免費額度後付費 | 允許；需金鑰 | 當「找不到時的備援搜尋」可考慮 |
| Bing Web Search API | ✅ 可行 | 後端 | 付費為主 | 允許；需金鑰 | 同 Google，二選一即可 |
| Fanza（DMM） | ⚠️ 勉強 | 強反爬／登入／地區 | — | 商業條款嚴格 | **不建議短期** |
| Getchu | ⚠️ 勉強 | HTML 爬、結構老舊 | — | 不明確 | **不建議短期** |
| 盜版／破解索引站 | ❌ | — | — | 法律／ reputational | **明確不做** |

### 1.4 與現有架構

| 層級 | 現況 | 標題搜尋擴充時 |
|------|------|----------------|
| 前端 | 單一查詢框＋候選卡 | 可加強：預設帶入「名稱」欄、顯示店家徽章、空結果引導（改原名／貼 URL） |
| Supabase RPC + `extensions.http` | 已跑 DLsite | 可繼續擴充；注意 DB 連線逾時、同步 http 阻塞 |
| Edge Function | 未用 | 多源／需 API key／較長解析時**更適合**；金鑰放 Function secrets |
| API key | 不需 | Google／Bing／部分第三方需；DLsite／Steam 可不需 |

`product_code` 欄位目前驗證 `RJ|BJ|VJ`：跨平台後應允許空或另存 `steam_appid` 等於 `metadata`，避免硬塞假 RJ。

### 1.5 成本與維護

| 項目 | 估計 |
|------|------|
| DLsite 關鍵字 | 金錢成本 ≈ 0；維護＝站點改版監控＋偶發封鎖 |
| Steam | ≈ 0；維護低 |
| Google／Bing CSE | 每月免費額度有限；超額付費；金鑰輪替 |
| 封鎖風險 | Admin-only、低頻、固定 UA／Cookie 可接受；公開開放搜尋會放大風險 |

### 1.6 建議產品流程（標題）

```text
站長輸入標題（可預填「名稱」欄）
  → 搜尋（先 DLsite；之後可加 Steam 等）
  → 候選列表：封面 + 標題 + 店家／社團 + 代碼或 AppID
  → 站長點「套用此筆」
  → 寫入 metadata 欄位（仍不填分數）
  → 手動評分與心得 → 儲存
```

空結果時：提示改日文原名、貼官方 URL、或（未來）切換資料源——**不要**靜默猜第一筆。

### 1.7 法律／ToS（標題）

- 僅供站長後台輔助填寫，非對訪客開放 bulk 爬取。
- 遵守各店家 ToS：合理頻率、保留來源連結、不轉售對方資料庫。
- 成人內容來源注意地區法與年齡門檻（既有 `adultchecked` Cookie 僅限伺服器端抓取）。

## 2. 以圖搜圖（封面／上傳圖）

### 2.1 技術可行性：**中**

| 子路徑 | 可行性 | 備註 |
|--------|--------|------|
| 上傳圖 → 第三方 reverse image API → 候選 URL／標題 | **中** | 需 Edge Function（CORS、金鑰、multipart） |
| 公開封面 URL → SauceNAO／iqdb by URL | **中** | 實作較上傳檔簡單 |
| Google Lens／Vision 商用 API | **中～高（技術）** | 付費、整合重；黄油封面辨識未必優於動漫索引庫 |
| 純前端直打第三方 | **低** | CORS、金鑰外洩 |
| 自建圖庫特徵比對 | **低（短期）** | 需累積自家封面向量庫，成本高 |

前端**已有**封面上傳 Storage，缺的是「上傳後／填 URL 後觸發搜尋」管線。

### 2.2 準確率預期

| 情境 | 預期 |
|------|------|
| 官方店家封面、未裁切 | 中～高（若該圖已被 SauceNAO／搜尋引擎索引） |
| 自制拼圖、浮水印、極端裁切 | **低** |
| 同人／黄油封面 | SauceNAO 對 Pixiv／部分同人索引較強；**DLsite 封面未必進庫** → 常只得到「相似插畫」而非商品頁 |
| 破解站重製封面 | 易指到錯誤來源或鏡像站 |
| 與標題併用 | 圖搜給候選 → 再用標題／代碼抓正規 metadata：**實務上最穩** |

**產品含義**：以圖搜圖適合「我忘記名字但有圖」的救援路徑，不適合當唯一自動填入來源。

### 2.3 可用資料源（以圖）

| 資料源 | 實際可用？ | CORS／反爬 | 付費／額度 | ToS | 評估建議 |
|--------|------------|------------|------------|-----|----------|
| **SauceNAO API** | ✅ | 需後端＋API key；禁匿名濫用 | 免費額度低；升級付費；有短時／日限 | 有使用條款；禁止洗限額 | **若做圖搜：首選輔助源** |
| iqdb / 3d iqdb | ⚠️ | 後端；無穩定官方商用 API | 非正式 | 灰色／不穩 | 可作備援，勿當唯一 |
| Google Lens（非官方刮） | ❌ | — | — | 易違 ToS | **不做** |
| Google Cloud Vision / Enterprise Image Search | ✅ | 後端＋GCP 金鑰 | 明確計價 | 合規 | 成本偏高，站長低頻場景通常不划算 |
| Bing Visual Search | ✅ | 後端＋金鑰 | 付費 | 合規 | 可評估，非必須 |
| TinEye API | ✅ | 後端＋金鑰 | 商用為主 | 合規 | 一般圖佳；黄油／同人索引未必夠 |
| 盜版圖床／破解站以圖搜 | ❌ | — | — | 法律風險 | **不做** |

### 2.4 與現有架構

| 層級 | 建議 |
|------|------|
| 前端 | 「以此封面搜尋」按鈕：用已上傳 Storage 公開 URL 或本機選檔 |
| Edge Function（建議） | 收圖／URL → 呼叫 SauceNAO → 正規化候選（標題、來源連結、相似度） |
| RPC/`extensions.http` | 可打 JSON API，但 multipart 上傳與金鑰管理較彆扭 → **圖搜優先 Edge Function** |
| API key | **需要**（SauceNAO 等）；存 Supabase secrets，勿進前端 |
| 串接詳情 | 圖搜命中含 RJ／DLsite URL 時 → 复用現有 `admin_fetch_game_metadata`；命中 Steam 則走 Steam 詳情 |

### 2.5 成本與維護

- SauceNAO：站長一人低頻通常可吃免費／低檔額度；公開給大量使用者會立刻撞牆。
- 維護：金鑰、限流錯誤處理、結果過濾（擋明顯無關／盜版鏡像）。
- 封鎖／停服：第三方可用性無 SLA → UI 需降級提示「請改標題搜尋」。

### 2.6 建議產品流程（圖片）

```text
上傳封面或貼封面 URL
  →（可選）先存 Storage
  → Edge Function 以圖搜圖
  → 候選：縮圖 + 相似度 + 來源站名 + 連結
  → 站長確認一筆
  → 若可解析出 RJ／官方 URL／Steam AppID → 再抓正規 metadata
  → 套用欄位（仍不填分數）
```

### 2.7 法律／ToS（圖片）

- 查詢圖可能被第三方短暫快取（SauceNAO 等有說明）——僅後台、勿上傳無關個資。
- 勿批量鏡像他人圖庫；結果連結指向原站，不熱鏈盜版資源。
- 成人封面送第三方前確認該服務允許 NSFW 查詢與帳號設定。

## 4. 明確建議

### 4.1 短期可做什麼

**值得做：把「標題候選列表」當主產品路徑（而非 RJ 附屬）。**

現況已是半成品：關鍵字 → `mode=search` → 候選卡 →「套用此筆」。短期投入應偏 **UX／文案／失敗引導**，而非重寫爬蟲：

- 文案改為「用遊戲名稱搜尋；有 RJ／URL 更準」
- 一鍵用「名稱」欄當查詢
- 空結果／僅部分匹配時的明確提示
- （可選）候選卡標示來源站

**不必**為了「不要依賴 RJ」而拿掉代碼路徑——代碼仍是最高準備援。

### 4.2 圖片搜尋是否值得做？建議路徑

| 判斷 | 說明 |
|------|------|
| **值得做嗎？** | **值得當 P1 輔助**，不值得當 P0 主路徑 |
| **建議路徑** | Storage／封面 URL → **Edge Function** → **SauceNAO** → 候選確認 → 命中則复用現有 DLsite／未來 Steam 詳情 |
| **不建議** | Google Lens 非官方刮、純前端金鑰、自建大規模以圖搜庫（短期） |

站長低頻使用時，圖搜的「找回忘記的標題」價值高於其準確率上限。

### 4.3 不建議做什麼

1. **全自動無確認直接填入**（含「永遠取搜尋第一筆」）——同名／譯名事故率不可接受。  
2. **依賴盜版／破解站**當 metadata 或圖搜來源。  
3. **短期硬接 Fanza／Getchu**（反爬＋ToS＋維護）除非有明確大量需求。  
4. **開放給非 admin** 的即時外站搜尋（封鎖與費用風險）。  
5. **自動填分數／心得**（與現有產品原則衝突）。

### 4.4 若同意實作：建議優先順序

| 優先 | 項目 | 預估性質 |
|------|------|----------|
| **P0** | 標題搜尋產品化：UX（名稱預填、提示、候選為主）、必要時修 DLsite 關鍵字空結果體驗；保留 RJ／URL | 小～中；多半不需新金鑰 |
| **P0.5** | Schema／文案：跨平台時 `product_code` 可空；`metadata.source` 標店家 | 小 |
| **P1** | Steam 標題搜尋併入同一候選列表（非 DLsite 作品） | 中；RPC 或 Edge Function |
| **P1** | 以圖搜圖 MVP：Edge Function + SauceNAO + 確認後复用詳情抓取 | 中；需 API key |
| **P2** | Google／Bing CSE 備援（限定官方域名） | 中；付費與解析 |
| **P2+** | Fanza／Getchu 等 | 高維護；預設擱置 |
